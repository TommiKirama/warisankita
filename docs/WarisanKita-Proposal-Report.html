01Executive Summary

WarisanKita is a mobile-first platform that turns Islamic estate planning — today a costly, intimidating, and widely neglected process — into a guided, 30-minute task that any Muslim adult can complete from a phone.

Across Malaysia, an estimated RM 70+ billion of Muslim wealth sits frozen in Amanah Raya and the Mahkamah Syariah because the deceased left no clear, valid wasiyyah. The consequences are not abstract: widows lose access to the family home, orphans cannot withdraw a late father's EPF, property is abandoned, and families fracture over disputes the Qur'an's inheritance laws were revealed to prevent. This is a failure of one of the five Ḍarūriyāt — Ḥifẓ al-Māl, the protection of wealth.

WarisanKita addresses this with three tightly integrated capabilities:

🗣️ Guided Drafting

A fiqh-grounded conversational assistant walks users through a valid wasiyyah step by step in plain language — enforcing rules such as the 1/3 bequest cap with cited evidence.

⚖️ Exact Faraid

A rule-based engine computes each heir's Qur'anic share using exact rational arithmetic — no rounding error — handling ʿaul, radd, kalalah, and mahjūb with verse-level citations.

🔗 Immutable Vault

Every will and amendment is written to a SHA-256 hash-chained ledger that makes forgery, loss, and post-death tampering instantly detectable.

This is not just a concept — a working prototype already exists

Unlike a typical paper proposal, this submission is backed by a complete, runnable full-stack prototype (React + TypeScript web client, Node/Express API). The core Islamic logic is real and verified: the Faraid engine passes 15 automated tests against classic textbook cases, and the blockchain vault demonstrates live tamper detection. Government and infrastructure integrations are transparently simulated — see the honesty matrix in §9.

05Product Walkthrough — Seven Core Features

All seven proposed features are implemented in the working prototype. Each carries its fiqh justification so the user is never asked to simply "trust the app".

1

AI Wasiyyah Drafter ● BUILT

A deterministic, fiqh-grounded conversational flow guides the user through a complete wasiyyah in seven steps — identity, assets, heirs, bequests, hibah/waqf, witnesses, and signing. It explains rulings (e.g. the 1/3 bequest cap; bequests cannot go to legal heirs) inline, with citations, in plain language.

Grounded in a local fiqh corpus — every guidance line is traceable to a source, never invented.
2

Faraid Calculation Engine ● BUILT & TESTED

The heart of the platform. Computes each heir's share from Qur'an An-Nisāʾ 11–12 & 176 using exact fractions — fixed shares (furūḍ), residuary (ʿaṣabah, "to the male twice the female"), exclusion (ḥajb), proportional reduction (ʿaul), surplus return (radd), kalalah, and the al-ʿUmariyyatān special case.

Validated by 15 automated tests against classic textbook scenarios. See §6.
3

Family Tree Builder ● BUILT

Users add heirs by relationship; the engine automatically detects who is excluded (mahjūb) and, crucially, explains why — e.g. "a son screens the grandsons and brothers; the father screens all siblings."

4

Blockchain Wasiyyah Vault ● BUILT (hash chain)

Every will and amendment becomes a block, cryptographically chained (SHA-256) to the one before. A built-in live tamper-detection demo proves that altering any past record is instantly flagged ("hash mismatch at block N"). This is a real hash chain standing in locally for Hyperledger Fabric.

5

Hibah & Waqf Planner ● BUILT

Plan lifetime gifts (hibah) and endowments (waqf) alongside the wasiyyah, with the 1/3 bequest ceiling enforced in code and surfaced to the user before they exceed it.

6

e-Signature & 2-Witness Module SIMULATED PKI

A pre-sign checklist, two-witness capture, and a deterministic signature digest model the path to Mahkamah-Syariah-recognised validity via MyDigital ID. The workflow is real; the government PKI is simulated (no student access to the real API) — see §9.

7

Faraid Education Hub ● BUILT

Bite-sized lessons and a verified Q&A on Faraid, hibah, and waqf — each answer carrying a citation — to raise a generation of financially-prepared, Shariah-literate Muslims.

Design principle running through all seven: transparency over trust. The app never says "just trust us" — it shows the verse, the ruling, the fraction, and the reason. That is what separates WarisanKita from a black-box calculator.

06The Faraid Engine — Technical Deep Dive

The credibility of the entire platform rests on getting the inheritance mathematics exactly right. This is where we invested the most engineering rigour.

Why exact fractions matter

Islamic shares are rational numbers — 1/8, 2/3, 1/6 — that frequently must be combined and reduced. Using floating-point arithmetic (e.g. 0.125 + 0.667) introduces tiny errors that, on a million-ringgit estate, can mean a heir receiving the wrong amount. WarisanKita implements a custom exact Fraction type (GCD-reduced numerator/denominator), so every share stays a precise rational from input to ringgit output. No rounding error — ever.

Concepts the engine encodes

Concept (Arabic)MeaningHandled?
FurūḍFixed Qur'anic shares for spouses, parents, grandparents, children, grandchildren, and all three sibling types.✔
ʿAṣabahResiduary heirs take what remains — "to the male a share equal to two females."✔
Ḥajb / MahjūbExclusion — e.g. a son screens grandsons & brothers; the father screens all siblings.✔
ʿAulProportional reduction when fixed shares exceed the estate (denominator "inflates").✔
RaddProportional return of surplus to fixed-share heirs when shares sum to less than 1.✔
KalālahEstate of one with no ascendant/descendant — maternal vs full/paternal sibling rules.✔
al-ʿUmariyyatānThe special spouse-plus-both-parents case (al-Gharrāwayn).✔

Madhhab note: shares follow the position common to the Sunni schools with a Shāfiʿī default. The grandfather-with-siblings (jadd wa ikhwah) case treats the grandfather as the father and emits a note recommending scholar review.

Worked example — the demo estate

Inputs

  • Gross estate: RM 1,200,000
  • Bequest (wasiyyah): RM 400,000 → within 1/3 cap
  • Net distributable estate: RM 800,000
  • Heirs: Wife, 2 Sons, 1 Daughter

Step-by-step

  1. Wife with children → fixed 1/8 = RM 100,000.
  2. Residue = RM 700,000 to children as ʿaṣabah.
  3. Split 2:1:1 → 5 parts of RM 140,000.
  4. Each son = 2 parts = RM 280,000; daughter = 1 part = RM 140,000.

Verified against classic cases

The engine ships with an automated test suite (15 tests, all passing) covering the scenarios examiners use to catch faulty calculators:

Husband 1/4 with childal-ʿUmariyyatān (H+F+M) al-ʿUmariyyatān (W+F+M)ʿAul 6→7 (husband + 2 sisters) Radd (mother + daughter)Mahjūb exclusions Granddaughter 1/6 "completion"Estate conservation = 100%
🧪
ʿAul worked live: for an estate with a husband and two full sisters, fixed shares (1/2 + 2/3) exceed the whole, so the engine scales the denominator from 6 to 7 — husband receives 3/7, the sisters share 4/7. This is the kind of edge case manual calculation routinely gets wrong.

Engineering choices that de-risk delivery

Repository-pattern data layer. Persistence sits behind an interface, so the JSON store used today can be swapped for PostgreSQL with no change to business logic.
Ledger abstraction. The hash chain implements the same append/verify contract a Hyperledger Fabric chaincode would expose — making the migration a substitution, not a rewrite.
Shared-origin proxy. The web client proxies /api to the Node backend, mirroring a production gateway and keeping the SPA and API on one origin.
LLM-ready drafter. The conversational flow is deterministic today but structured so a Llama-3 + RAG pipeline can drop in behind the same interface when budget allows.
